# Brief: make the omnibar truly thin

Status: backlog (Paul, 2026-10-19 10:46 AM PT). Do this before we share the omnibar with the community.

## Why
The contract already holds. Apps register through `omnibar-providers-slot` and `omnibar-query-results-slot`, Cohort Builder and ChartSearch use nothing outside `src/omnibar-contract/`, and the bar's own rows register the same way. But the bar itself still knows ChartSearch, the query store and its own patient search by name. If we say "thin contract with a UX to register into", the code should back that up.

## What
1. Hints come from `asksModel`. Replace the hard-coded "Enter to ask ChartSearch" and "Ask ChartSearch" (`src/omnibar/omnibar.extension.tsx` around 704) with text built from the declaring view's `asksModel`.
2. No special `ask` id. Replace the hard-coded `ask` in `src/omnibar/commands.ts` (and its uses in `omnibar.extension.tsx`, `query-results/query-results-views.ts`, `query-results.page.tsx`) with a flag a view sets in its routes.json `meta`, so any app can declare a command that sends the question to its model. ChartSearch adds that one line to its routes.json.
3. Wristband scan on Enter. Either let any patient provider earn it through a `meta` flag that config must grant, or record in decisions.md that only the built-in patient search gets it, as a safety exception. Paul to pick.
4. Move the query store provider, and the code it loads when a chart opens (`src/index.ts`), into its own app. Patient search, chart lookup and go-to pages stay built in for now, as decisions.md records, and move to their owning apps later.
5. Delete the leftover ChartSearch settings in `src/config-schema.ts`, and use neutral examples in the comments in `src/omnibar-contract/types.ts`.

## Out of scope
- Any change to the contract version or its fields beyond the one new `meta` flag.
- Moving patient search, chart lookup or go-to pages out.

## Done when
- Searching `src/` outside `omnibar-contract/` for "chartsearch", "ask" as an id and "querystore" finds nothing but tests and docs.
- `/ask` works on o3 exactly as it does today, declared only by ChartSearch's flag.
- A test provider in the test suite declares its own model command and gets the same behaviour as `/ask`.
- Tests, lint, typecheck, build and translations extract pass. Grok code review approves.
- README, AGENTS.md and decisions.md match the code.
